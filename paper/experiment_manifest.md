The IEEE-CIS mode is a two-party linked sanity benchmark using the exact `TransactionID` intersection and observed `isFraud`; it is not a four-industry benchmark. Source files remain authorized local inputs, are not redistributed, and are not required by ordinary CI. The run records local source-file SHA-256 checksums, train-only party-local preprocessing, pseudonymous exported entity IDs, and the standard reproducibility bundle.

The NPI benchmark is exact linkage across real public provider records from distinct US government/provider data products using the authoritative 10-digit NPI. It must not be described as private cross-company collaboration. Source releases, selected columns, release dates, checksums and intersection coverage must be frozen in the evidence bundle.

External FATE/SecretFlow rows are considered complete only when the normalized JSON result produced by `scripts/run_external_comparator.py` exists in the released evidence. Pending external measurements must remain marked pending; no manually estimated comparator numbers are allowed.

The protected logistic path has a deliberately narrow guarantee: PSI protects the entity intersection according to the selected backend threat model, while clipped-Gaussian accounting covers configured active-to-passive residual releases. Other protocol messages remain outside that guarantee.

The publication artifact builder reads `predictions.parquet`, `training_history.csv`, experiment CSVs and benchmark CSVs to generate the paper table and figures. The repository must not substitute manually entered measurements when a required artifact is absent; missing measured inputs are treated as errors.
