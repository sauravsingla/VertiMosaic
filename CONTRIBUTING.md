# Contributing

Thank you for improving VertiMosaic.

1. Open an issue for substantive behavioral or protocol changes.
2. Keep VFL terminology precise: different feature columns over aligned/overlapping entities.
3. Do not introduce accelerator-only, graph, proprietary, or credential-requiring dependencies into the default install.
4. Add tests for protocol, privacy-boundary, leakage, and reproducibility changes.
5. Never commit external raw datasets, API keys, Kaggle credentials, or private row-level values.
6. Run `make all` and relevant security checks before requesting review.
7. Document privacy claims conservatively. Data locality is not equivalent to cryptographic security.

Pull requests should explain the research or engineering rationale, tests run, and any claim/limitation changes.
